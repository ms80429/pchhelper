다음 세션이 이 대화 없이 바로 이어받을 수 있게 정리한다. 추가 메모: $ARGUMENTS

1. **상태 점검** (결과를 숨기지 말 것. 실패는 실패로 기록)
   - `npx tsc -p .`
   - `npm test`
   - `npm run validate` → `reports/data-validation.md` 요약표 확인
2. **`docs/HANDOFF.md` 갱신** — 통째로 다시 쓰되 아래 구조 유지, 80줄 이내:
   - `## 현재 위치`: CLAUDE.md §6의 몇 단계인지, 한 줄 요약
   - `## 검증 상태`: 1의 결과 (PASS/FAIL 항목과 실패 이유)
   - `## 사용자 대기`: 사용자의 결정·데이터가 필요해 막혀 있는 것 (없으면 "없음")
   - `## 다음 할 일`: 우선순위 순 번호 목록. 1번은 다음 세션이 바로 시작할 수 있을 만큼 구체적으로 (파일·명령)
   - `## 알아둘 것`: 코드만 봐서는 모르는 함정·결정 사항과 그 이유 (이미 SOURCES.md / champions-diffs.md에 있는 건 링크만)
   - `## 세션 기록`: 맨 아래에 `- YYYY-MM-DD: 한 줄 요약` 추가 (기존 줄 유지, 10줄 넘으면 오래된 것 삭제)
   이번 세션에서 바뀌지 않은 내용도 사실과 다르면 고친다.
3. **커밋**: `git status`로 확인 후 변경 사항을 커밋. `node_modules`, `reports/.vitest.json` 등 `.gitignore` 대상은 제외.
   메시지는 이번 세션 작업 요약. 검증 FAIL 상태여도 커밋하되 메시지에 명시.
4. 사용자에게 5줄 이내로: 한 일 / 검증 상태 / 사용자 대기 항목 / 다음 할 일.
